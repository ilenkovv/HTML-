# Web Master — финализация внутреннего кодового этапа

Дата: 2026-09-01

## Зафиксированный внутренний контур

- Линейный UX мастера сохранён: файл → пользователь → загрузка → проверка → настройка приложения → размещение → готово.
- Конфигурация сущностей, полей, связей, ролей, AI-доступа и админ-панели валидируется сервером.
- Единые лимиты конфигуратора вынесены в `APP_CONFIG_LIMITS`.
- Runtime policy применяет entity-specific разрешения поверх wildcard-разрешений.
- CRUD записей выполняется server-side с проверкой роли и scope владельца записи.
- PostgreSQL runtime-схема содержит FK к `app_projects`, cascade cleanup, аудит, метрики, динамическую уникальность JSON-полей и проверку cardinality связей.
- AI-доступ запрещён к sensitive-полям и регулируется конфигурацией поля.
- Публичный deployment runtime использует versioned delivery и безопасные заголовки.
- REG.RU не использует пароль личного кабинета: интеграция строится через отдельный HTTPS deployment-agent и server secrets.
- Собственный домен и PWA не имитируются, пока соответствующая инфраструктура реально не подключена.

## Quality gate

Канонический полный исходник содержит команды:

- `bun run typecheck`
- `bun run typecheck:agent`
- `bun run test`
- `bun run test:agent`
- `bun run build`
- `bun run build:agent`
- `bun run lint`

Полный gate должен быть выполнен в среде с установленным Bun и зависимостями до production-публикации.

## Что осталось только для ввода в эксплуатацию

1. Применить последние Supabase migrations в целевом проекте.
2. Развернуть deployment-agent на подготовленном REG.RU VPS.
3. Настроить Nginx/HTTPS и отдельные server secrets.
4. Выполнить реальные интеграционные тесты Supabase/Storage и REG.RU.
5. Только после успешных интеграционных проверок публиковать production.

Эти пункты не являются незавершённой внутренней логикой приложения; это внешний deployment/operations этап.
